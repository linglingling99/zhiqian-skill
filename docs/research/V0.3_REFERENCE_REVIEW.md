# V0.3 成熟项目对照与取舍
核验日期：2026-09-16。下面是来源支持的做法与本项目自己的设计决定，不是“高星保证质量”。不采用无证据的社区评分，也不复制整套上游运行时。

| 对照对象 | 来源支持的重点 | 本版采用 | 明确不照搬 |
|---|---|---|---|
| Anthropic skill-creator | 从少量例子提炼普适方法、控制提示词膨胀、渐进加载；真正测评要独立成对运行 | 主入口缩短、按事件路由；假设示例与独立实测分层 | 用同一作者模拟的分数宣称效果 |
| Superpowers writing-skills | 经验需可迁移；可机械检查的约束用程序；有压力与反例测试 | 核验机械回执的真实程序测试，保留适用/不适用条件 | 所有小任务强制完整开发链 |
| Planning with Files | 状态落盘、按选定任务恢复；标准 Skill 与宿主生命周期增强不同 | 保留 TASK/LOG 接续与绑定；说明 SOFT 能力限制 | 自动扫描其他会话、默认安装 Hooks |
| GitHub Spec Kit analyze | 检查跨产物覆盖、术语漂移、遗漏与冲突；分析不能冒充执行 | 输入输出链、依赖影响、变更后再验收 | 把每阶段都变成额外一份长文档 |
| Basic Memory memory-capture | 更新同一主题的当前理解，不不断追加互相冲突的旧决定 | 当前 TASK 与事件 LOG 分离 | 引入它的服务或直接复制其代码/文本 |
| Deep Agents README | 模型能做什么受工具约束；安全边界不能靠模型自律 | 只读脚本不自称沙箱；HARD 以宿主证据为准 | 移植整套 Agent harness |
| Agent Skills 标准 | SKILL.md 加可选 scripts/references/assets；按需加载 | 相同入口与兼容路径，可选单个 Python 检查器 | 把任何一个框架的偏好误称为标准强制规定 |

## 关键纠偏（本项目设计判断）
1. 不能用“更多规则”修复所有衔接问题，应规定每轮的输入、结果、写回与下一步。
2. 不能同时要求“先拥有全部 ID 才能读文件”和“先读入口才知道 ID”。新流程先确认授权根，再最小读取身份。
3. 模板不能既要求全部字段齐全，又禁止无价值档案。新模板保留必要语义，允许省略不适用部分。
4. 经验必须同时保留证据和反例，不能把一个案例变成普遍规则。
5. “我不懂”不能与“你决定”合并成授权。
6. 关键词存在、哈希一致、独立模型有效是三个不同命题；测试必须分开。
