# Human AI Collab V0.2｜修复与升级计划

> V0.2 不是“再加几个模板”，而是把 V0.1 的思考结构真正转成可验证的生产协作。

## 重新定性 V0.1

V0.1 没有证明“装 Skill 明显比不装更强”。它主要增强了需求分层与思考结构，但最终产品、数据沉淀、工具效率和交接没有形成稳定优势；同时发生 Scope / 数据污染事故。

因此 V0.2 的核心问题是：

> 一个普通用户只提出一个不完整想法时，AI 能否自己补齐大众基线、研究成熟同类、理解用户差异、形成生产资料、稳定执行、真实同步，并让下一位 AI 接手。

## V0.2 主线

```text
Scope Boundary
→ 读取合法资料
→ 最小结果层澄清
→ 同类产品 / 领域研究
→ Table Stakes / Best Practices / Avoid / User Delta
→ Write-through 生产资料
→ 能力缺口路由
→ 执行 / Demo
→ 证据验收
→ 状态同步
→ Handoff
```

## P0 修复

### Scope Firewall

复杂任务第一次文件操作前明确：

- `WORK_ROOT`
- `ALLOWED_READ_ROOTS`
- `ALLOWED_WRITE_ROOTS`
- `EXPLICIT_EXCEPTIONS`

默认不读取父目录、兄弟任务、其他项目、共享 memory。**数据归属优先于路径包含。**

### Context Contamination Stop

误读其他任务/用户上下文时：

- `CONTEXT_CONTAMINATED = TRUE`；
- 停止需要独立性的分析/审计；
- 不允许用“我保证不用”继续；
- 需要独立结果时换干净会话，重做受污染阶段。

### Write-through State

`TASK.md` 是 Current Truth。确认后的：

- 需求 `R-*`
- 决定 `D-*`
- 假设 `H-*`

必须在进入下一关键动作前真实写入。执行前、重大变更后、完成前都做 State Sync。

## P1 增强

### 产品 / 领域研究

新产品、网站、App、小程序、工具、服务若存在成熟同类，优先研究高信号代表，提炼：

- `TABLE_STAKES`
- `BEST_PRACTICES`
- `AVOID_LIST`
- `USER_DELTA`

研究影响方案时必须进入 `RESEARCH.md` 并关联 D-*。当新增来源不再改变大众基线、风险或关键决定时停止研究。

### 小白友好

- 问结果，不问技术术语；
- 每轮 1–2 个真正影响方案的问题；
- 用户说“你决定 / 你看着办 / 我不懂”时进入 `DELEGATED_MODE`；
- 可逆、低风险、免费、不外发事项由 AI 自主决定；
- 付费、发布、账户授权、敏感数据、重要删除等仍需用户确认。

### 执行纪律

- 同类失败连续两次 → `ROOT_CAUSE_CHECK`，禁止直接第三次撞墙；
- 验证证据只有 `ACTIVE / SUPERSEDED / INVALID`；
- 后台进程、临时目录、旧证据未处理前不得声称完成。

### 文件治理

- `PROFILE.md`：只有至少 1 条“用户已确认 + 跨任务有价值”的信息才创建；
- `RESEARCH.md`：只有真实研究影响方案时创建；
- `versions/`：只在重大里程碑按需使用；
- `INDEX.md` 保持极简。

## 验收 Gate

### Scope
- 越界读取：0
- 越界写入：0
- 跨项目/跨组污染：0

### State Sync
- 已确认 R/D/H 同步率目标 ≥ 95%
- 研究驱动决策可追溯率 = 100%

### 用户负担
- 不高于 Baseline
- 不把专业技术选择扔给小白

### 产品
- 第三方盲评至少不弱于 Baseline；
- 在需求命中、完整度、风险处理或可继续迭代上应有明确增量。

### Handoff
新 AI 只拿 workspace：
- 能恢复目标、状态、决定、假设、研究与下一步；
- 已回答问题重复询问 ≤ 1；
- 能直接完成一个小变更并复跑验证。

- `main` 保留 V0.1 历史；
- `v0.2-eval-fixes` 完成修复与开发验证；
- 静态校验 + 行为契约预检通过后快进合并；
- 重新在 WorkBuddy 做真实 A/B 和 Handoff；
- 只有真实行为达到 Gate，才把 0.2 从 RC 定义为有效版本。
