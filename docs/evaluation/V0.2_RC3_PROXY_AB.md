# V0.2 RC3 Proxy A/B 预检

> 2026-09-16。开发者代理测试，不是两个真正独立模型，不能替代 WorkBuddy 真实 A/B。

## 任务

标准 eval `research-challenges-idea`：

> 我觉得做一个只有三个按钮的客户管理小程序就够了，你帮我直接做方案。

两组完成第一版后，同时追加：

> 核心方向改一下：首版不要微信小程序了，先做手机网页，完全本地使用，其他你继续。

## Baseline

普通强 AI 能直接形成很好的三入口产品：今日跟进 / 客户 / 快速新增；有状态、跟进、搜索、本地存储、验收和开发交接。最终产品质量本身很强，说明 Skill 不能靠“会做产品方案”证明价值。

## RC2 暴露的缺陷

Skill 组虽然有 Research、R/D/H、Current Truth 和 Handoff，但平台变更后仍出现部分同步：

- TASK Goal 残留“打开小程序”；
- 后续升级残留“订阅消息提醒”；
- 自称完成 State Sync，但没有检查所有派生产物；
- 自然执行没有完整采用核心文件模板字段。

因此新增：

- `SCHEMA_GATE`：核心文件从对应模板起步；
- `CHANGE_IMPACT_GATE`：核心变更先列影响文件；
- `STALE_TERM_SCAN`：旧语义分类 `HISTORICAL_OK / UPDATE_REQUIRED / INVALID`；
- 新 eval：`platform-change-reconciliation`。

## RC3 复跑

RC3 能把平台变更写成结构化 CHANGE_SET，并同步 TASK / RESEARCH / ACTIVE outputs / Handoff / 验收。旧平台名称只允许出现在明确的否定、替代或历史上下文，ACTIVE 产品规格和开发交接保持当前 Web/PWA 方案。

## 成本

- Baseline：2 个文件，约 4.1 KB。
- Skill RC3：6 个文件，约 15.2 KB。

Skill 的增量主要来自研究可追溯、反证、状态资产、变更传播和交接；**不是产品创意碾压**。流程/文本成本也明显更高。

## 判定

`PROXY_PASS_WITH_CAVEATS`

- RC3 值得进入下一轮真实 WorkBuddy A/B；
- 不能根据本 Proxy 宣称 Skill 已经成功；
- 真正需要继续验证：Token/积分、工具调用、真实 HARD Scope、独立 Handoff、重复 3 轮后的方差。
