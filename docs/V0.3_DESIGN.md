状态：本地实现与检查完成，GitHub 发布待本轮同步复核；用户已授权自主优化与 GitHub 更新，不要求再次确认设计。

## 不变的主线
理解用户与任务 → 辩证核查 → 必要调研 → 决策与生产资料 → 按需调用能力 → 执行验证 → 可迁移资产 → 用真实经验改进下一次协作。简短任务直接做，不设强制档案。

## 架构选择
不继续叠加 Gate，也不引入 Agent runtime/数据库/自动 Hooks。保留单个 Skill 入口及现有四个 reference 路径；将所有能力接入同一个“状态—行动—证据—更新”循环。每个模块说明输入、输出、触发、停止与下一步，研究不是固定大流程，经验不是强制模板。

人类可读的 TASK 是需求/决策真源；LOG 只保留事件事实。产品规格只有交付确实需要时独立生成，否则 TASK 兼任。多文件或真实交接时可生成机器校验回执，回执只保存索引、修订与哈希，不再维护一份自然语言需求。

## 统一接口
Context：任务/会话身份、授权根、可用能力、当前用户目标。
State：需求、决定、假设、来源、动作、产物、验收与未决项。
Delta：本次新增或修订的信息及受影响的对象。
Evidence：实际来源/工具结果/文件版本，不等于 AI 自述。
Next：完成、一个可逆动作、必要澄清、受阻或污染交接。

## 重要修正
“我不懂”只改变解释方式，不等于委托或授权。“你决定”不授权付费/外发/敏感访问。既有 SOURCE/PROFILE 只能按明确作用域读取。判断可以自行处理，不等于修改用户确定范围。旧关键词命中只触发人工/模型语义审查，不自动认定错误。

## 只读回执校验器接口
`python scripts/check_workspace.py --root TASK_ROOT --receipt checks/receipt.json [--delivery]`
退出 0：机械检查通过；1：回执/产物不一致；2：参数/输入读取问题。输出 JSON。绝不修改资料、执行回执内命令、联网或扫描兄弟目录。此工具不是安全沙箱，也不能证明语义正确或模型一定遵守工作流。
