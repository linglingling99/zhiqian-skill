# 测试分层与公平性

V0.3 不把关键词出现等同 AI 执行。测试分四层：包结构 lint、真实检查器单元测试、作者构造的假设产物、独立宿主 A/B。前三层通过不推出第四层通过。

## 本轮可复跑
`python tests/validate_skill.py`；`python tests/validate_behavior_contract.py`；`python tests/validate_hypothetical.py`。
最后一项读取合成夹具 zip 并在临时目录故障注入，不调用模型。不把夹具答案塞进安装的 Skill 包。

## 后续真正的 A/B
先冻结版本、输入、授权、模型和预算。A 无此 Skill，B 安装指定版本；两者普通安全指令与工具相同。若验证版本进步，另外比较旧版与新版，不混成无 Skill 对比。

采用相同用户响应政策，不因为 B 提问就给独有的需求；允许两组自主研究。输入/条件变化要同时提供并记账。并行共用主机的负载/缓存/全局技能可影响结果，需记录；两聊天框或路径约定不构成硬隔离。使用宿主真实可验证的环境分隔。

工作开始前冻结共同验收规则；产品评分不使用 PROFILE/TASK 这些特定文件名作为加分项，不以篇幅或模板遵守率证明用户收益。过程自评分不是最终评分。成本缺失写 null，不能填0；污染/失败/重跑保留，成本按首次、恢复、复跑、审计分开，不能把审计成本当工作成本。

运行中记录真实调用/回执、模型版本、技能版本、起止与用户介入，不重构假聊天。最终快照被冻结后，只读审计不能补作业。交接另外开独立会话，只给合法工作资料。评委匿名看成果；评分标准可事先冻结但不把期望答案/私有测试喂执行模型。真实重复次数不足时报告个案，不宣称显著优势。

`evals.json` 是供主持人设计实验的题目和期待，不是实际跑分。`fixtures/` 是作者公开示范，不能用于证明泛化，也不能把示范答案交执行组。
