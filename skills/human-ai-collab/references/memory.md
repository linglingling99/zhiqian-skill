# 本地资料落盘与接续（memory）

来自 planning-with-files 的取精去杂：保留"按任务目录恢复、先读当前决定、重要发现/错误落盘、方法与个人数据分离"，去掉"YAML hooks、CLAUDE 路径、会话存储扫描、强制 2-action 计数与自动停止钩子"。

## 核心思想

上下文窗口像内存（易失、有限），文件系统像磁盘（持久、不限）。凡是重要内容，写进本地文件。

## 方法与个人数据严格分离

- **公共 Skill 包**（`skills/human-ai-collab/`）：只放方法、规则、模板。
- **用户资料主目录**（用户自己指定）：放用户自己的资料。

结构约定：

```text
用户资料主目录/
├── INDEX.md            # 当前资料位置、任务入口、恢复办法
├── PROFILE.md          # 可选；确认过的工作背景与协作方式
└── tasks/
    └── <稳定task-id>/
        ├── TASK.md     # 当前需求、有效决定、状态、验收、下一步
        ├── LOG.md      # 增量确认、变更、动作与检查
        ├── RESEARCH.md # 有真实研究才建
        ├── materials/  # 用户资料 / 获准来源
        ├── outputs/    # 实际成果
        └── versions/   # 里程碑快照
```

用户通常只需看 `PROFILE.md` 和当前 `TASK.md`；其他文件由 AI 按需维护。`INDEX.md` 必须用相对路径并可迁移；未知日期、身份不造值。

上述文件的空白模板见公共 Skill 的 `assets/templates/`（index / profile / task / research / log），新建时从那里复制，不写到 Skill 安装目录。

## 接续（换会话 / 换 AI 后）

1. 先读 `INDEX.md` 定位任务入口，读当前 `TASK.md` 和最近的 `LOG.md`。
2. 用"五问重启"核对状态：
   - 我在哪（当前阶段）？要去哪（剩余阶段）？目标是什么？学到了什么（RESEARCH）？做过了什么（LOG）？
3. **读取之后才宣称接续**。本地资料可携带，不代表任何平台会自动读取。
4. 未实现自动恢复钩子时，靠用户显式提交本地入口文件恢复；不宣称自动跨会话记忆。

## 记录规则

- **增量写**：每次有新增事实或决定，只更新受影响的小节，不整份复制。
- **写前先读**：写入前读当前版本，避免覆盖并发变化；可用临时文件+替换降低半写风险（需实测并说明环境）。不能靠一句"版本控制"就保证不丢数据。
- **单一决策来源**：当前有效内容集中在 `TASK.md`；历史 `LOG.md` 只作证据，不能重新覆盖当前已明确替代的决定。
- **每次范围改变、执行前、交付时保存版本**（快照到 `versions/`），不必每轮复制整个文件夹。

## 文件职责

| 文件 | 用途 | 何时更新 |
|------|------|----------|
| `TASK.md` | 目标、范围、需求、决定、状态、验收、下一步 | 目标/决定/状态变化时 |
| `LOG.md` | 增量确认、变更、动作、检查、错误、恢复点 | 有动作/错误/检查时 |
| `RESEARCH.md` | 来源、证据、结论、限制、核验日期 | 有真实研究时 |
| `PROFILE.md` | 确认过的协作偏好与背景 | 用户确认新偏好时 |

## 错误与失败

- 每个错误都记进 `LOG.md`：错误、第几次尝试、解决方式。
- 失败后**不要重复同一动作**：换方法、换工具、换思路。
- 三次仍失败时升级给用户，说明试过什么、具体错误是什么、请用户给方向。

## 数据边界

- 每项个人观察保留：来源、用户确认状态、适用范围、更正记录。
- 敏感资料默认不外发、不进公开测试；用户拒绝记录时尊重。
- 用户要求删除个人内容时，不在隐藏副本中保留，只保留不含已删内容的必要删除说明。
